## Why this document exists

The audit of 2026-09-16 found these ten assets declaring `categoryReview.document` =
`docs/art_reviews/EQUIPMENT_PREMIUM_V2_REVIEW.md`, a review whose accepted source, Actions run and hash
gates cover the premium-v2 batch. Nothing in that document covers these ten, so the manifest was making
a coverage claim the review could not support. The claim is corrected here: the manifest now names this
document for exactly these ten ids, with `status: accepted`, meaning "the contract below is satisfied",
not "a rendered acceptance pass was reviewed".

## What is verified, and by what

| Property | Measured by |
|---|---|
| File present, byte-identical to the shipped ledger (`docs/asset_hashes.json`) | `AssetIntegrityTest`, `PremiumAssetContractTest`, validator gate *asset hash ledger* |
| 192×192 Hero-socket frames, normalized pivot `(0.5, 0.12)`, 25-bone list, clip names/frame counts, atlas coordinates | `PremiumAssetContractTest` (asserted against `EquipmentCatalog`, not against literals) |
| 1920×768 RGBA atlas page, one 96×96 icon, `alphaMode STRAIGHT_RGBA`, `rigProfile hero-socket-v2` | `PremiumAssetContractTest`, validator gates *silhouette* / *edge safety* / *no resampling signature* |
| No upscaled copy: the sheet is not a resampling-grid copy of another tier | validator gate *no resampling signature*, `tools/visual/classify_master_tier.py` |
| Rendered at the reviewed tier for the class (`2/12` overlay tier for equipment) | validator gate *reviewed-tier pinning* |
| Revision label appears in the document that is supposed to cover the asset | `ReviewLabelBindingTest`, `tools/visual/write_review_labels.py --check` |

## What is *not* claimed

- No rendered acceptance review exists for these ten sheets. The premium-v2 review's accepted render
  run, its all-frame audit and its per-item hash gate never saw them.
- The images are therefore covered by the runtime contract and by byte-level provenance, not by a
  visual acceptance pass. Adding that pass is tracked as roadmap item R5.6 (per-batch review documents
  regenerated with the render that produced them).

## Per-asset hashes

Hashes are not copied into this file by hand; they live in the generated ledger
`docs/asset_hashes.json`, keyed by the sheet paths in the table above, and are written by
`tools/visual/restore_runtime_tier.py`. A hand-typed hash would be a new claim instead of a
measurement.
