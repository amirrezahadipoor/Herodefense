# Hero Defense — independent re-audit, 2026-09-17

**Score: 731 / 1000, of which 731 / 920 are in scope.** The full rubric is worth 1000 points across ten
categories; release preparation (80) is excluded by the owner's own instruction, so the reachable total is 920.
**Gate 1 (≥ 900) is not met, and this document says by how much and where.** Gate 2 (≥ 900 / 1000 on the
experience rubric, roadmap R16.4) is not assessed here at all: it is about how the game feels, this audit has no
human playtest behind it, and it would be dishonest to score it from a repository.

The previous audit (`AUDIT_2026-09-16.md`, 505 / 920) was a one-page scoreboard per category. This one is the
same rubric at the same granularity as the first was asked for: every category is broken into the sub-items that
make it up, each sub-item names the measurement that decides it, and **every point that is not earned has a plain
reason beside it**. Nothing here is inherited: each figure below was re-derived from a table row, a
`docs/perf/runs/` record, a test result or a file on disk, on 2026-09-17.

## 4. The five largest deductions, in plain words

1. **−25 — Persian and RTL do not exist.** The game is English-only in a left-to-right layout. Every other
   deduction is about polish; this one is about who can read the game at all.
2. **−17 — the hero cannot move.** Combat is "point and wait": the hero is locked to the centre of the arena
   during a wave, so positioning — the part of this genre players spend their attention on — is not a decision.
3. **−12 — store screens and the accessibility options are missing** (7 + 5), which makes the game harder to use
   than it needs to be on a phone with a large font or a colour-blind player.
4. **−11 — the optimiser still beats the human policy.** A player who always chooses the mathematically best
   build still clears more waves with less pressure, which means the difficulty curve assumes a player who does
   not exist.
5. **−10 — nothing ships compressed.** The encoder, the containers and the loader are all in place and measured,
   and the catalog is still PNG because the encoder's own quality bar is not met — a memory win that is real
   arithmetic and not yet a real saving.

## 6. What is still open, in the roadmap's own terms

- **Gate 1:** needs 900 of 920. This audit finds 731. The 169 points are the deductions in §3, and 60 of them are
  one item: Persian and RTL, the Back button, accessibility and the store screens.
- **Gate 2 (R16.4, ≥ 900 / 1000):** not assessed here. It needs a playtest, and the roadmap's R9–R16 items —
  movement, build identities, secrets, narrative, engagement — are what would move it.

## 8. The limits of this audit

This is a rubric measured against artefacts, not a review of the game as a player meets it. It cannot see how a
wave *feels*, whether the boss music lands, or whether the tutorial is understood rather than merely present —
those are Gate 2's job and they need a human. Where a sub-item could only be judged by reading code (onboarding
quality, the "variety per wave" note in §3) this document says so rather than converting the reading into a
number. And a score is only useful if it moves: the previous audit's 505 and this one's 731 were both derived
from the same ten categories with the same weights, so the 226-point difference is work, not a new ruler.
