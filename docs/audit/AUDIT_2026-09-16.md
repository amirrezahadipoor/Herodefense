# Independent audit — 550 / 1000 (commit `49fa799`, 2026-09-16)

This is the audit that produced the roadmap this repository is now executing. It is committed to the
repository on purpose: the criticism is part of the project record, not something to be forgotten after
the score is written. The per-item plan that answers it is
[`docs/ROADMAP_TO_1000.md`](../ROADMAP_TO_1000.md).

## Method

- Full clone of `amirrezahadipoor/Herodefense` (153 MB including 101 MB of `.git` history).
- Read of the 17,406 lines of `core` main source and 11,783 lines of test source; reading of the
  workflows, the Blender/Python asset pipeline and the documentation set.
- Git history review: 352 commits, all authored in the same four-day window and by one author string.
- GitHub API review: tags, releases, and the 811 CI runs.
- Numeric image analysis with Pillow/NumPy: equal-pixel-pair ratio, 2×2 block analysis, NEAREST
  round-trip tests, per-sheet classification against the pre-Phase-76 revision.
- A real `:core:test` run on JDK 17 (the reviewer's own environment, not the project's cache):
  **BUILD SUCCESSFUL, 146 test classes, 517 tests, 0 failures, 0 errors, 0 skipped, 6 m 12 s**.
- Raw measurements recorded throughout: decoded texture bytes, per-sheet pixel dimensions, test counts,
  CI durations, and the asset classification between the reviewed revision and HEAD.

Not reviewed, and therefore neither credited nor deducted: playing the game by hand (touch feel,
long-run fun), running the APK on a physical device, judged audio quality, and whether the CI Blender
renders are byte-identical to the committed sheets.

## The finding that dominated the score

Phase 76 (commits leading to and including `5374f2c`) claimed an HD upgrade. Measurement showed that
**93 sheets were an exact NEAREST 2× copy of the previous revision and 7 more were an exact 1.5× copy**:
107 of 107 sheets in the batch carried no new detail, quadrupling decoded texture memory
(1,277 MiB total) for nothing. The tests that should have caught it were the same commits that disabled
the checks: `assertTrue(true)` bodies, `|| true` conditions, commented-out SHA-256 assertions and two
lowered thresholds.

That is why the roadmap starts with integrity recovery instead of features: with those checks disabled,
no later claim in the repository can be trusted, including honest ones.

## Estimated recovery

The review estimated roughly **+285 points** of recoverable work at the time, i.e. a ceiling near 835,
and noted that the estimate is a ceiling, not a promise: part of the remaining score depends on how the
game actually feels to a human player, which the audit explicitly did not judge.
